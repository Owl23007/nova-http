# 简介

Nova 是一个使用 TypeScript 编写、直接构建在 Node.js TCP 之上的 HTTP 框架。

它提供路由、中间件、子应用、请求上下文与生命周期 Hooks，并以流式模型贯穿请求体读取与响应写入，支持背压控制。

Nova 不追求用更多约定隐藏请求处理过程，而更关注请求从连接、解析、分发到响应的完整执行链路。我们希望开发者能够清楚地理解数据如何流动，并在需要时显式控制每一个阶段。

因此，Nova 在接口设计上保留了许多与 Express 相近的使用习惯，但底层请求处理链路由框架重新实现。数据库、认证、业务校验与部署方式则保持开放，希望由你来根据自身需求选择和组织。

## 适用场景

成熟的 HTTP 生态已经能够覆盖大多数 Web 开发需求。我们并不试图重新定义这些上层能力，而是选择回归更接近 TCP 数据流的请求处理模型，让开发者能够直接观察和控制数据从连接到响应的流动过程。

Nova 适合用于构建：

- JSON API 与轻量 HTTP 服务
- 文件下载与流式传输
- SSE 等长连接响应
- 对请求与响应流有精细控制需求的服务
- HTTP 协议处理、请求分发与框架机制相关的实验和扩展

Nova 的生产包没有第三方运行时依赖。HTTP/1 解析、消息定界、连接管理与请求分发均由框架自身实现。

如果你希望了解这些能力如何组成完整的请求处理链路，可以继续阅读[架构与边界](../framework/architecture)。

## 使用边界

Nova 的 `get()`、`use()` 与中间件调用方式与 Express 等框架较为接近，但请求、响应与上下文均由 Nova 自身定义，并不以兼容 Express 中间件生态或 Node.js HTTP API 为目标。

因此，依赖以下实现细节的中间件不能直接视为兼容：

- Express 特有的 `req` / `res` 扩展
- Node.js `IncomingMessage`
- Node.js `ServerResponse`

Nova 的核心能力围绕自身的请求处理模型组织。应用侧的扩展可以通过普通函数、中间件、Hooks 与子应用进行组合，当前未提供特定的插件注册机制。
